Problemas de batería, apagado anómalo, BIOS y Secure Boot

Está pensado para entregárselo a otro asistente técnico (Claude) para continuar el diagnóstico sin repetir innecesariamente procedimientos ya realizados.

4. PROBLEMA ACTUAL DE SECURE BOOT
===============================================================================

Con Secure Boot activado, después del logo de MSI aparece:

Secure Boot Violation
Invalid signature detected.
Check Secure Boot Policy in Setup.

Al aceptar el mensaje con OK, la notebook vuelve a MSI Click BIOS.

PRUEBA CRÍTICA:
Cuando Secure Boot Support se desactiva, Windows arranca normalmente.

Esto demuestra:
- Windows puede arrancar.
- El SSD es accesible.
- Existe un Windows Boot Manager funcional al menos hasta el punto de poder iniciar Windows con Secure Boot desactivado.
- El fallo se produce específicamente cuando el firmware intenta validar la cadena de arranque bajo Secure Boot.

10. INTERPRETACIÓN ACTUAL DEL SECURE BOOT VIOLATION
===============================================================================

La evidencia más fuerte es:

Secure Boot OFF:
-> Windows arranca normalmente.

Secure Boot ON:
-> BIOS encuentra el Windows Boot Manager.
-> Se produce:
   "Secure Boot Violation - Invalid signature detected"
-> Vuelve a BIOS.

Esto apunta a un problema en la cadena de confianza/validación de arranque UEFI, no a una imposibilidad general de arrancar Windows.

Posibilidades aún abiertas:

A) El firmware no confía en el certificado/cadena que firma el componente EFI utilizado para arrancar Windows.

B) La base de datos de Secure Boot (DB/DBX) no contiene o no conserva la cadena de confianza requerida.

C) El bootloader EFI de Windows es antiguo, fue reemplazado, está corrupto o no corresponde a una cadena de firma aceptada por la configuración actual.

D) Hay una interacción/bug de firmware en la BIOS E18IMS.30D relacionada con Secure Boot/certificados.

E) El evento de apagado/ciclo de encendido dejó alguna variable EFI/NVRAM en un estado inconsistente.

Ninguna de las anteriores, por separado, está demostrada.

===============================================================================
11. CONTEXTO ACTUAL DE CERTIFICADOS SECURE BOOT
===============================================================================

Debe considerarse el contexto actual de 2026:

Microsoft está realizando la transición desde certificados/autoridades Secure Boot de 2011 hacia certificados de 2023, y los certificados de 2011 tienen fechas de expiración en 2026.

Esto es relevante porque un equipo puede:
- mostrar Secure Boot como Active,
- tener Factory Default Keys,
- pero aun así no aceptar un boot manager si la cadena de confianza disponible en DB no contiene el certificado necesario o fue restaurada/reemplazada incorrectamente.

Por eso no debe asumirse que "Factory Default Keys instaladas" equivale automáticamente a "toda la cadena de confianza actual de Windows está correcta".

27. CONCLUSIÓN TÉCNICA DE TRASPASO
===============================================================================

El sistema NO presenta un fallo general de arranque de Windows.

La evidencia decisiva es:

Secure Boot OFF -> Windows arranca normalmente.
Secure Boot ON -> BIOS rechaza la cadena de arranque por:
"Invalid signature detected"

Las Factory Default Keys fueron instaladas sin resolver el problema.

Por lo tanto, la investigación debe centrarse en la cadena de confianza de Secure Boot:
- DB/DBX/certificados;
- certificados Secure Boot 2023;
- Windows Boot Manager/EFI;
- política de firma;
- comportamiento de la BIOS E18IMS.30D;
- posible recuperación de Secure Boot mediante la herramienta oficial de MSI/Microsoft.

El problema de batería y el evento de power cycling son antecedentes importantes, pero su relación causal con Secure Boot no está demostrada.

Este documento diferencia intencionadamente entre hechos comprobados e hipótesis para que otro asistente pueda continuar el diagnóstico sin asumir conclusiones no verificadas.
